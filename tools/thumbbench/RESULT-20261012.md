# 缩略图加载策略实测：v1.51 → v1.52

日期：2026-10-12
机器：本机（AutoCAD 2020 所在机器）
样本：真实图库 `D:\2025室内设计精品图库V2.0悟空整理制作`

## 测什么

同一批真实 DWG、同一份 `DwgPreviewReader`（直读 DWG 内嵌预览）、同样的 8 路并行、
同样的 PNG 落盘，**只有排队策略不同**：

| | 策略 |
|---|---|
| **v1.51** | 点开分类 → 把该分类**全部**条目登记进队列 → 后台一直做到最后一张；滚动期间不停 |
| **v1.52** | 点开分类 → 只登记"预览区看得见的一段 + 上下各半屏余量"；**滚动期间后台完全停摆**，停下 140ms 后按新视口续装；已出过的图落在磁盘缓存里，滚回去秒出 |

基准台：`tools/thumbbench`（net47 控制台，直接把插件里的 `DwgPreviewReader.cs` 编进来，
不走任何 CAD API，因此可离线复跑）。

复跑命令：
```
tools\thumbbench\bin\Release\net47\ThumbBench.exe "<图库目录>" 24 4
                                                  ↑目录  ↑每屏可见数 ↑滚动屏数
```

## 实测结果

### 样本 A：单分类「人物合集\立面人」—— 304 个图块 / 25.7 MB

| 指标 | v1.51 | v1.52 | 变化 |
|---|---|---|---|
| 首屏就绪 | 5 ms | 1 ms | **快 80.1%**（5.04×） |
| 点开分类后后台忙多久 | 1216 ms | 1 ms | **少 99.9%** |
| 整个周期工作量 | 304 张 | 228 张 | 少 25.0% |
| 整个周期后台累计忙 | 1216 ms | 48 ms | 少 96.1% |
| 滚动期间后台偷做 | 247 张 | 0 张 | 完全停摆 |

### 样本 B：分类「家具」—— 743 个图块 / 2.37 GB

| 指标 | v1.51 | v1.52 | 变化 |
|---|---|---|---|
| 首屏就绪 | 34 ms | 20 ms | **快 40.2%**（1.67×） |
| 点开分类后后台忙多久 | 1236 ms | 20 ms | **少 98.4%** |
| 整个周期工作量 | 743 张 | 228 张 | 少 69.3% |
| 整个周期后台累计忙 | 1236 ms | 80 ms | 少 93.5% |
| 滚动期间后台偷做 | 713 张 | 0 张 | 完全停摆 |

### 样本 C：整个图库根目录 —— 4437 个图块 / 5.28 GB

| 指标 | v1.51 | v1.52 | 变化 |
|---|---|---|---|
| 首屏就绪 | 25 ms | 15 ms | **快 41.3%**（1.70×） |
| 点开分类后后台忙多久 | 1982 ms | 15 ms | **少 99.2%** |
| 整个周期工作量 | 4437 张 | 228 张 | **少 94.9%** |
| 整个周期后台累计忙 | 1982 ms | 112 ms | 少 94.3% |
| 滚动期间后台偷做 | 2767 张 | 0 张 | 完全停摆 |

## 结论

**首屏（用户真正等待的那一段）快 40% ~ 80%**；
**点开分类后 AutoCAD 后台的占用时间少 98.4% ~ 99.9%**；
**总工作量（读 DWG + 解码 + 落盘）少 25% ~ 94.9%**，分类越大省得越狠。

一句话：4437 个图块的库，v1.51 要点开就闷头做满 4437 张、后台忙满近 2 秒；
v1.52 只做屏幕上那 36 张，15 毫秒收工，剩下的看哪儿做哪儿。

## 诚实记录：v1.52 的一处代价

"滚过 4 屏的全程耗时"这项，两者基本持平（全库 1956 ms vs 1925 ms），
在 300~750 个图块的中等分类上 v1.52 反而多花约 0.6 秒——
因为 v1.51 在用户开始滚之前就已经把整个分类做完了，滚到哪儿都是现成的图；
v1.52 要等滚动停下 140 ms 才出下一屏。

换来的是：v1.51 那 0.6 秒的优势，是用"打开分类时后台忙满 1.2 秒 +
滚动期间继续做掉 713~2767 张"换的。这些后台工作会和滚动绘制抢 I/O 与主线程，
正是下拉列表发涩的来源。v1.52 下拉期间后台一张都不做，滚动只做滚动。

## 附：v1.52 的三个实现要点

1. `RebuildList` 不再 `RequestThumbnails(_currentBlocks)`（整个分类），
   改为 `LoadVisibleScopeNow()`：只登记当前视口 + 上下半屏余量。
2. `ThumbnailService.SetVisibleScope(scope)`：滚出视口的排队项从 `_pending/_fallback/_meta`
   里撤销并同步销账（不清 Keys 会导致那张图以后永远排不上队）。
3. 滚动闸门 `IsScrolling`：滚轮事件与 `LVM_GETTOPINDEX` 变化都刷新时间戳，
   距最后一次滚动 < 140 ms 期间 `ProcessPendingThumbnails` 只调 `DrainDoneOnly()`
   —— 只收活（已做好的图照样显示），不派活、不开 Database。
